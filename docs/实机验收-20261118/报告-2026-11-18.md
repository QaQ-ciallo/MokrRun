## 4. 有效运行时间核算（更正）

以**末次 tick 打印**为共同截止点，扣除主动暂停与两次冻结：

| 事件 | 时刻 / 时长 |
|---|---|
| 开始命令 | 07:32:18.799 |
| 人脸冻结 #1 | 07:33:01.226–07:33:08.048，**6.822 s** |
| 人脸冻结 #2 | 07:33:32.153–07:33:36.309，**4.156 s** |
| 主动暂停 | 07:36:14.192–07:36:29.737，**15.545 s** |
| 末次 tick 打印 | 07:37:13.289（1286.8 m / 836 步） |
| 结束命令 | 07:37:17.538 |

```text
开始命令 → 末次 tick        = 294.490 s
暂停 + 冻结合计              = 26.523 s
可运行窗口                   = 267.967 s
引擎里程折算运动时间          = 1286.8 / 4.8 = 268.083 s
差值                         = 0.116 s
```

**结论**：引擎里程与「扣除暂停/冻结后的可运行窗口」基本一致（差 0.116 s，属首 tick 基准、
异步状态应用与打印精度量级）。**此前报告「引擎因卡顿少计约 10%」的结论作废**——那是拿
298.739 s（开始→结束命令）与引擎运动时间直接比较、且未扣除暂停与冻结造成的错误。
末次打印到结束命令之间还有 4.249 s 无末端读数，不能判为漏计。

因此**不据此调整 `effDt` 或任何性能恢复策略**，也不把性能损失归因于 FuckTSN 日志量。

## 7. 归档：关闭 FuckTSN 时的拦截（不认定已解决，关系未定位）

- 现象：**关闭 FuckTSN** 时，点开始弹出「系统检查到疑似模拟定位，已被系统记录，请卸载虚拟定位软件并关闭开发者选项后再试」；
  **开启 FuckTSN** 后不再出现。
- 证据：`evidence-01-antimock-gate.txt` + `01-module-home.png` / `02-target-before-start.png` / `03-after-start.png`。
- **关系未定位**：弹窗出现时引擎处于 `mode=0`，但本模块仍有部分 hook 在未开始时工作
  （如 `AntiDetect` 的 isMock/包列表过滤、`LocationProbe` 的注册捕获），
  因此**不能**用「当时 mode=0」推断与模块无关；也不排除是目标应用 2.0.26 新增判定或 FuckTSN 的副作用。
- 处理：作为外部模块依赖/兼容性问题单独归档，**不认定已解决**；反检测移植
  （开发者选项、AppOps MOCK_LOCATION、定向包查询等）另行立项，不在本轮修改代码。
