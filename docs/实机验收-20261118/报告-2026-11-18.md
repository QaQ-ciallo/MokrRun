- 已用有效运动时间 = 1286.8 / 4.8 = **268.1 s**（占 298.7 s 墙钟的 90.2%）：主线程偶发卡顿导致 tick 延迟，
  按 A2 设计（`effDt = min(dt, 2 s)`，超窗不补算）因此里程/步数同步少计约 10%。**距离与步数彼此一致**：
  836 步 ≈ 268.1 s × 3.12 步/s = 836.5 步。
- 步数下发值为 `sStepBase + sSteps`（本场路线重置时 `sStepBase` 已归零），应用侧自行按增量计数，
  因此**不要求应用绝对值与引擎本场步数相等**。

## 6. 观察到但未判定为缺陷的现象

1. **引擎少计约 10%**：tick 因主线程卡顿延迟，`effDt` 上限 2 s 不补算（设计如此）。本轮 FuckTSN 签名/日志量很大，
   卡顿更明显；若要 1:1 墙钟，需要另议恢复策略（不在本轮修改）。
2. **启动时 GPS 轨迹异常提示**（07:32:20）：质量伪装字段已生效（`qr fake applied -> status=2`、`gnss emit count=16`），
   但应用仍提示了一次；点「继续跑步」后正常，且未再出现。原因未定位，**不下结论**。
3. **掉登录**：应用自身在 07:33:08 回到登录页并要求重新授权（非我方操作，用户已确认）。
4. **偏离区域提示**：模块 mode=0 后 3.4 s，应用依据真实定位判定偏离并暂停自身计时，属应用行为。

## 7. 归档：关闭 FuckTSN 时的拦截（不认定已解决）

- 现象：**关闭 FuckTSN** 时，点开始弹出「系统检查到疑似模拟定位，已被系统记录，请卸载虚拟定位软件并关闭开发者选项后再试」；
  **开启 FuckTSN** 后不再出现。
- 当时模块 `mode=0`、未接管定位（`config via / command via / tick dist=` 全部 0 命中），与本模块的模拟行为无因果关系。
- 证据：`evidence-01-antimock-gate.txt` + `01-module-home.png` / `02-target-before-start.png` / `03-after-start.png`。
- 处理：作为**外部模块依赖/兼容性问题**单独归档；反检测移植（开发者选项、AppOps MOCK_LOCATION、定向包查询等）
  另行立项，不在本轮修改代码。**不得**以本轮通过推断该问题已解决。

## 8. 结论（严格限定组合）

在 **MokrRun 1.0.120 + FuckTSN 开启 + 体适能 2.0.26 + 当前设备设置** 下：

- 引擎侧核心机制**全部通过**：启动、平稳计步（无万级跳变/回退）、三分钟时点正常、暂停冻结、继续不补算、
  结束交还真实定位、旧冻结超时不重启引擎、定位 hook 命中真实载体、补发确认零失败、真实硬件计步未混入。
- **未通过 1 项**：应用侧里程相对引擎偏低 16%（1.08 km vs 1.287 km），与应用自身掉登录窗口量级一致，
  需在没有掉登录干扰的场次复测。
- **未达标**：应用自身规则要求 2.0 km / 1200 步，本轮 1.08 km / 777 步（06:01）未达标——
  这是运行时长与掉登录丢点共同造成，不是「步数异常跳变」类问题。
