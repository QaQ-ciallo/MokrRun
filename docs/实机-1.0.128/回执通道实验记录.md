## 当前可确认与不可确认

可确认：
1. 目标进程发起的 `ContentProvider.call()` 在当前设备上**从应用身份**不可用（前台/后台都一样）；
2. 发往模块 App 的广播在同一次操作中没有到达（处于 Pending 或未投递，两者都观察到过）；
3. 目标进程**读**该 Provider 是正常的（引擎每 tick 读 run/cfg 成功）；
4. shell 身份 `query` 正常。

不可确认（不要再当结论用）：
- 究竟是 MIUI 的 provider 白名单、`call()` 的启动语义，还是广播冻结策略；
- 换一台非 MIUI 设备是否同样失败；
- 目标应用进程内的 Xposed 注入是否影响 ContentResolver 的调用身份。

## E4（下一轮，最小验证）：ResultReceiver / Binder 回调

设计：模块启动目标时把 `ResultReceiver`（Parcelable，跨进程 binder）放进 Intent extras；
目标在 `prepareSession()` / `applyConfirm()` 完成后直接 `rr.send(mode, bundle)`。
回调是**模块 → 目标方向**传递的 binder，目标调用它不需要访问模块的 Provider、不需要广播、
也不抢前台。

需要验证的三点：
1. 冷启动路径（Intent 带 ResultReceiver）能否拿到回调；
2. 目标已在运行时（CMD 广播带 ResultReceiver）能否拿到回调；
3. 回调是否受 MIUI 对「跨进程 binder 调用」的额外限制。

日志：`logcat-resultreceiver.txt`，23:17:36–23:17:58，2.49 MB，

```text
23:17:44.056 MokrRun: ack receiver registered android.os.ResultReceiver
23:17:44.057 MokrRun: ack via ResultReceiver op=prepare
23:17:44.057 MokrRunAckProbe: result op=prepare session=77b9e762-… ok=true mode=3
23:17:44.059 MokrRun: ack attempt=1 op=prepare provider=false …   ← 旧通道仍在失败，不影响回调
```

界面侧：体适能前台显示，悬浮窗已出现且状态为「待配置」，首页状态同步为已启用。

一个必须记住的坑：把模块 APK 里的 Parcelable（ResultReceiver 子类）放进 Intent 时，
目标进程默认用体适能的 classloader 反序列化会抛 `BadParcelableException`；
读取前必须 `intent.setExtrasClassLoader(MotionEngine.class.getClassLoader())`。

结论：D 方案（模块传句柄、目标直接回调）在 MIUI 上可用，且不依赖 Provider、广播或前台切换。
下一步按 D 实现完整版：冷启动（Intent）与目标已运行（有序广播 + `getResultReceiver()`）两条路径，
并把旧的 Provider/广播 ack 尝试降级或删除。

## E6 定位修复（1.0.149/1.0.150，00:08–00:10）

用户报的两个现象：

1. 打开模块首页，地图停在默认坐标（天安门）；
2. 进「修改起点」点「使用我当前的位置」，位置偏约 50 m、落到马路上。

实测根因：

- 首页 `renderMap()` 在没有缓存定位时把 `curLat/curLon` 传 0，home.html 就保持
  Leaflet 默认视图 → 天安门；
- 「修改起点」还在用 `LocationHelper.requestOnce()`，它是**缓存优先**：
  实机拿到的是几十秒前的 GPS 缓存 `23.067437,113.973532`，
  而同一时刻现取的网络点 `23.067488,113.975219`，两者经度差约 0.0017°（≈170 m），
  这就是「偏到马路上」的来源。

修复：

- 首页：无缓存、无起点时自动 `doLocate()` 一次，居中当前位置；不再停默认坐标。
- `LocationHelper.requestFresh(..., preferPrecise)`：选起点时先等精度 ≤20 m 的点
  （GPS 通常 3–8 m），超时才用记录下的最优点/缓存兜底；精度写进 toast。
- `OriginActivity` 改用 `requestFresh(preferPrecise=true)`，并在回调里刷新坐标显示。

实机结果（00:08–00:10）：

```text
MokrRunLoc: fresh network wgs=23.070274,113.970262 gcj=23.0674880,113.9752191 acc=30.0
```

- 首页：进入即居中当前位置（截图 61），状态「当前位置已更新：精度 30 m」，不再是天安门；
- 修改起点：坐标显示 23.067488,113.975219（与首页一致），十字准星落在宿舍区而不是马路（截图 64）。

限制：室内只有网络定位（30 m 精度），`preferPrecise` 会等 12 s 后回落到这个点；
室外有 GPS 时会取 ≤20 m 的点。用户仍可拖动准星微调。
