## 6. 安装升级与回滚

- **升级**：`adb install -r MokrRun-1.0.153.apk`（保留 prefs 与路线）。升级后若 LSPosed 作用域丢失，
  重新勾选目标应用并强制停止目标应用一次（本机实测重装会掉作用域）。
- **回滚（有条件）**：`adb install -r -d MokrRun-<旧版本>.apk` 只在「旧包 versionCode 更低、签名与当前包一致、
  设备/ROM 允许降级安装」时可用；正式签名包在部分设备（含部分 MIUI/HyperOS）上会被系统拒绝降级，
  `-d` 并不能保证在所有设备生效。若被拒绝，只能卸载后重装旧版本——**这是有损操作**：
  会清空模块 prefs（路线、草稿、会话），需要重新配置。
- **清理（有损）**：`adb shell pm clear com.mokrun.app` 会清掉路线、草稿与会话，不等同于「无损重置」。

## 11. 1.0.153 发布后的问题与 1.0.154 / 1.0.155（2026-11-20 09:15–10:26）

### 11.1 1.0.153 的启动期崩溃（已修复）

实机现象：体适能开始跑步 → 闪退。

```text
Unable to start activity ...FaceLiveV3Activity:
  BadParcelableException: ClassNotFoundException when unmarshalling: ...PointData
Caused by: ClassNotFoundException ... on path: DexPathList[[dex file "InMemoryDexFile[...]"],
  nativeLibraryDirectories=[.../com.mokrun.app-.../base.apk!/lib/arm64-v8a, ...]]
```

结论：**模块回归，非目标应用问题**。`IntentBridge` 从 1.0.151 起对每个 Activity 的 Intent
无条件 `setExtrasClassLoader(模块 loader)` 且不恢复；该 Intent 被应用复用后，
它读自己的 `PointData` 就用模块的 InMemoryDexFile 加载器 → 找不到自己的类 → 启动期崩溃。

### 11.2 1.0.154 的次生问题（已修复）

1.0.154 改为「拷贝一份 Bundle 再设模块 loader」，闪退消失（10:20 实测 FaceLiveV3Activity 正常打开、
崩溃缓冲为空），但 LazyValue 仍绑定原 Bundle，回执句柄读不出来：

```text
read result receiver failed BadParcelableException:
  ClassNotFoundException when unmarshalling: com.mokrun.app.MainActivity$5
```

于是回退到广播（MIUI 上收不到），表现为**模块界面一直显示「未启用」**，而引擎其实已是 PREPARED。

### 11.3 1.0.155 修复与实测

- 读回执期间：`getClassLoader()` 记下宿主原加载器 → 设模块 loader → 读完 `finally` 立刻还原；
- 不再长期改写宿主 Intent，也不再依赖 Bundle 拷贝。

| 检查 | 结果 |
|---|---|
| 启用（模块界面） | 「已启用 · 待配置」，`ack via ResultReceiver op=prepare ok=true`（截图 88） |
| 确认（远起点二次确认） | 首点被拒（532 m > 90 m）→ 再点下发成功：`ack via ResultReceiver op=confirm` + `confirm applied … mode=RUNNING` |
| 启动跑步 | 进入 `V4SportActivity`，引擎 tick 推进（dist 341.2 m、steps 221），**崩溃缓冲为空** |
| 回归 | `test_intent_classloader` 4/4（新增 `restores_previous_loader`）；八套全绿 |
