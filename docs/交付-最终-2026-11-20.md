## 2. 本轮修复（提交前审查两项边界）

| 编号 | 问题 | 修复 |
|---|---|---|
| P1 | 取消草稿后，迟到的定位回调仍会调用 CONFIRM 发送入口 | `LocationHelper` 增加请求代际 `sGen` 与 `cancelFresh()`：取消/销毁时 `removeUpdates` 并推进代际，旧回调被丢弃；`DraftActivity` 增加 `confirmGen`、`destroyed`、草稿快照与会话复核，取消按钮与 `onDestroy` 都撤销请求；下发前再校验 session 与草稿快照 |
| P2 | 120 s 缓存兜底被确认页标成 `age=0`，绕过 30 s 新鲜度校验 | `FreshCallback.onFresh` 增加 `(long ageMs, boolean fromCache)`；新点、粗精度兜底、缓存兜底各自回传真实年龄与来源；`DraftActivity` 按真实年龄执行 `RouteDraft.check`，缓存命中时提示「使用 N 秒前的位置」；30 s 阈值保持不变（未放宽） |
| P2 | `IntentBridge` 读完若干 extras 后才设 ClassLoader | 前置到读取任何 extras 之前（含冷启动 `onCreate` 与热启动 `onNewIntent`） |
| — | 过时注释 | 清理「最小验证用」「第二条回执通道」与「退后台必然导致 Provider 失败」等已作废表述 |

## 7. 发布说明（草稿，未发布）

> **MokrRun 1.0.153**
> - 新增「启用 → 预备 → 草稿 → 确认 → 运行」两段式流程：未确认前目标应用显示真实位置、不推进不计步。
> - 回执改走 ResultReceiver（binder），按 session/token 匹配并带超时；不再把「发送成功」当成「已启用」。
> - 定位：「定位当前位置」只居中当前位置、不改路线；首页自动定位；选起点现取定位并优先精确（≤20 m），缓存兜底会提示真实年龄。
> - 悬浮窗：待配置 / 运行中 / 已暂停三态，暂停冻结位置、继续沿原路线、结束交还真实定位。
> - 已知限制：应用自身的 GPS 异常提示与掉登录未定位根因；应用与引擎三分钟同窗增量尚未完成验证。
