# PREPARE/CONFIRM 回执通道：方案修订版（2026-11-19 23:20）

> 修订原因：上一版把「shell 能读、目标读不到」判成「MIUI 后台限制」，并据此给出 A/B/C 三案。
> 实机判别实验（见 `实机-1.0.128/回执通道实验记录.md` E3）表明：**模块 App 处于前台、进程存活时
> 同一条 Provider 调用依然失败**，所以「后台限制」这一根因不成立，A/B 两案的前提与细节都需要重写。

## 0. 现在能确认的事实

| 编号 | 事实 | 证据 |
|---|---|---|
| F1 | 目标进程 → 模块 Provider 的 `call()` 失败（前台/后台都一样） | E1 `ack attempt=1..4` 全失败；E3 前台同样失败 |
| F2 | 目标进程 → 模块的 ACK 广播未送达（曾观察到 Pending） | E1 无 `MokrRunAck`；`dumpsys activity broadcasts` 曾见 Pending |
| F3 | 目标进程**读**同一 Provider 正常（引擎每 tick 读 run/cfg） | 引擎日志 `idle mode=…`、`provider route ignored` 等 |
| F4 | shell 身份 `content query` 正常 | E2 |
| F5 | 模块 App 前台 + 有前台服务时，F1/F2 仍复现 | E3（pid 28855、topResumedActivity=com.mokrun.app） |

不能确认的：MIUI 白名单 / `call()` 启动语义 / 广播冻结策略 / 设备是否特例 / 注入是否影响调用身份。
**在 F1–F5 基础上，任何“方案”都应当先做最小验证再谈改动量。**

## 1. 上一版 A 案的错误（已作废）

原写「目标写外部目录 + 模块申请 `MANAGE_EXTERNAL_STORAGE` 读」。
**错误**：Android 11+ 的 `MANAGE_EXTERNAL_STORAGE` 并不授予读取**其他应用** `Android/data/<pkg>` 的权限，
该目录受 scoped storage 保护；shell 能读是因为 shell 有特殊权限。所以 A 案不是“加个权限”就能成立，
按原文开工必然失败。若要保留“目标写文件”的思路，可行前提只有：
- 目标把文件写到**公共目录**（`/sdcard/Documents` 等）且模块持有 `MANAGE_EXTERNAL_STORAGE`（权限重、审核风险）；
- 或设备 root（本项目模块侧一直避免要 root）。

## 2. 上一版 B 案的错误（已作废）

原写「目标 `startActivity` 到模块的透明 `AckRelayActivity`，用 signature 级自定义权限保护」。
**错误**：注入代码运行在**体适能进程、体适能 UID** 下，它不是模块签名，拿不到模块的自定义 signature 权限；
要求该权限 = 透明页必然拒绝体适能。若改为不设权限（`exported=true` 且无保护），任何应用都能拉起该页，
暴露面不可接受。另外后台拉起 Activity 仍受 MIUI 限制。

## 3. 修订后的候选方案

### D（首选）：ResultReceiver / Binder 回调

**通道**：模块在**它自己发起的方向**上把 `ResultReceiver` 塞进 Intent/broadcast extras；
目标完成状态切换后直接 `rr.send(code, bundle)`。这是「模块 → 目标」传句柄、目标调用句柄，
不需要目标访问模块的 Provider、不需要反向广播、不抢前台。

| 项 | 评估 |
|---|---|
| 改动量 | 小～中：`MainActivity` 构造 `ResultReceiver` 并放入 Intent（~20 行）；`IntentBridge`/`CommandReceiver` 解析并交给 `MotionEngine`（~30 行）；引擎在 prepare/confirm 后 `send`（~30 行）；删除或降级现有的 provider/广播 ack 尝试（~-40 行） |
| 风险 | ① 目标→模块的 binder 回调是否被 MIUI 拦（**必须实测**，但方向与广播不同，属进程间 binder，通常放行）；② 跨进程回调需在 UI 线程外发送，注意线程；③ 目标进程被杀时回调丢失 → 仍保留超时提示 |
| 语义 | 强：与现在的“回执”等价，且是同一个 binder 会话 |
| 可验证 | 好：JVM 可用替身 ResultReceiver 验证 send 时机与内容；实机一次点击即可看到 |
| 估时 | 实现 2–3 h + 实机验证 0.5 h（若被拦，直接转 E） |

### E（备选）：模块侧轮询公共目录

目标把 `mokr_ack.json` 写到**公共目录**（如 `Documents/MokrRun/ack.json`），模块持
`MANAGE_EXTERNAL_STORAGE` 读取。

| 项 | 评估 |
|---|---|
| 改动量 | 中：引擎落盘（~40 行）+ 模块轮询（~70 行）+ 权限引导 UI（~50 行） |
| 风险 | 权限重（所有文件访问）且要用户手动开；公共目录对其他应用可见（回执里只有 session/token/ok，无敏感数据，但仍应写明）；Android 11+ 需要 `MANAGE_EXTERNAL_STORAGE` 才能写公共目录以外的路径 |
| 语义 | 强 |
| 估时 | 0.5–1 天 |

### F（兜底）：弱确认

| 项 | 评估 |
|---|---|
| 改动量 | 小（~50 行）：`EnableFlow` 增加 `SENT_UNCONFIRMED`，界面显示「已发送，请在体适能确认已启用」+ 手动标记 |
| 风险 | 语义弱：无法证明引擎真在 PREPARED；但不会谎报成功 |
| 估时 | 0.25–0.5 天 |

## 4. 建议顺序

1. **先做 D 的最小实机验证**（只验证回调能否到达，不接 UI）：
   - 冷启动路径：Intent 带 `ResultReceiver`；
   - 已运行路径：CMD 广播带 `ResultReceiver`。
   两条都通 → 按 D 实现完，再补 JVM 回归与实机复测。
2. D 被拦 → 再评估 E（要接受重权限）或 F（接受弱语义），不要同时上两条通道。
